# Code Standards

Formatters and linters enforce what can be enforced. This page covers the rest, and why. CI runs every check listed here; a PR that fails one doesn't merge.

## General

- **Clarity over cleverness.** Code is read far more than it's written. Prefer obvious control flow, descriptive names and small functions with one job.
- **Make invalid states unrepresentable.** Encode invariants in types (enums, newtypes) instead of comments and runtime checks.
- **Pure core, I/O at the edges.** Compiler phases and the engine are pure functions of their inputs. Files, network, clocks and environment variables are touched only in the outermost layers (napi, adapter, runtime).
- **No dead code, no commented-out code, no TODO without an issue.** Write `// TODO(#42): …`.
- **Comments explain why, not what.** Every non-obvious rule copied from React or Next.js behaviour cites its source: file and version, e.g. `// React 19.3 ReactFizzConfigDOM: text separator <!-- --> between adjacent text nodes`.
- **Dependencies are a cost.** Add one only when it's maintained, Apache-2.0-compatible, and clearly better than a few dozen lines of our own. Justify it in the PR.

## Rust

| Tool | Setting |
|---|---|
| Toolchain | Stable, pinned in `rust-toolchain.toml`; edition 2024; MSRV = pinned version |
| Format | `rustfmt` (`rustfmt.toml`); CI: `cargo fmt --check` |
| Lint | `clippy` with `all` + `pedantic` as warnings, workspace `[lints]` table; CI: `cargo clippy --all-targets -- -D warnings`. Individual `allow`s need a comment |
| Supply chain | `cargo deny check` (advisories, licenses, bans, sources) |
| Tests | `cargo nextest run`; doc tests with `cargo test --doc` |

Rules:
- **No `unwrap`, `expect`, `panic!`, `todo!` or `unimplemented!` in library code.** Enforced with `clippy::unwrap_used` etc. They're fine in tests, benches and build scripts. When an invariant truly can't fail, use `expect("<why this can't fail>")` with an `#[allow]` and a comment.
- **`unsafe`:**
  - `#![forbid(unsafe_code)]` in every crate except `napi`.
  - In `napi`, every `unsafe` block has a `// SAFETY:` comment (`clippy::undocumented_unsafe_blocks`).
- **Errors:**
  - Libraries return `Result<T, E>` with a crate error enum (`thiserror`), whose variants carry context.
  - No `anyhow` in libraries (fine in binaries and tests).
  - Errors are never stringly typed across crate boundaries.
- **Public API:**
  - `missing_docs` is denied for public items in `ir` and `engine`.
  - Every public function documents its errors (`# Errors`) and any panics.
  - Keep public surfaces small: `pub(crate)` by default.
- **Performance:**
  - In hot paths, no allocation per node or per request where a reused buffer works.
  - Write into `&mut Vec<u8>` / byte buffers, not `String` concatenation.
  - Measure before and after (criterion).
- **Naming:**
  - Standard Rust API Guidelines (`snake_case`, `UpperCamelCase`, conversions `as_`/`to_`/`into_`).
  - Types are named after domain terms used in ARCHITECTURE.md.
- **Modules:** one concept per module. `mod.rs`-free layout (`foo.rs` + `foo/`).

## TypeScript / JavaScript

| Tool | Setting |
|---|---|
| Runtime | Node.js pinned in `.node-version` (24 LTS); ESM only (`"type": "module"`) |
| Package manager | pnpm workspaces, version pinned in `packageManager` |
| Types | `tsconfig.base.json`: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`, `isolatedModules`; CI: `tsc --noEmit` |
| Lint | ESLint flat config with `typescript-eslint` `strictTypeChecked` + `stylisticTypeChecked`; zero warnings |
| Format | Prettier (default options, 100 columns) |
| Tests | Vitest; Playwright for browser tests |

Rules:
- **No `any`.** Use `unknown` and narrow it. **No non-null `!`** except with a comment.
- **Validate at boundaries.** Data from outside the process (requests, manifest files, env) is parsed into typed values once, at the edge.
- **Errors:**
  - Throw `Error` subclasses with a stable `code`; never throw strings.
  - Don't swallow errors. A deliberate fallback logs the reason at debug level.
- **Async:** no floating promises (`@typescript-eslint/no-floating-promises`). Every promise is awaited or explicitly handled.
- **Exports:** named exports only, and a package's public API is its `src/index.ts`.

## Generated code

- Generated files (encoders, programs, manifests) carry a header: `// @generated by tsx2rs <version>; do not edit`.
- They are deterministic and never checked in, except as test snapshots.

## Git hooks (lefthook)

- **pre-commit:** format and lint the staged files (fast).
- **commit-msg:** commitlint.
- Hooks are a convenience. CI is the source of truth, and bypassing hooks doesn't bypass CI.
